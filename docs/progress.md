# progress.md

세션 간 진행 상태 기록. 에이전트와 팀원은 세션을 시작할 때 이 파일과 최근 커밋 로그를 먼저 읽는다.

## 규칙

- **상태 값**: 대기 / 진행 / 통과 / 보류. "통과"는 관련 검사(테스트·스크립트·링크 확인 등)를 **실제로 실행한 증거**가 있을 때만 쓴다. 통합 `verify` 명령은 아직 없다(H-04).
- Task를 지우거나 완료 조건을 바꾸지 않는다. 바꿔야 하면 사람이 결정하고 `docs/SPEC.md`부터 고친다.
- Task 목록은 `docs/SPEC.md`의 마일스톤 표(W1~W4)를 옮긴 것이다. 주차 밖 Task를 임의로 추가하지 않는다.
- 세션을 마칠 때는 아래 표와 세션 로그를 갱신하고 무엇을 했는지 알 수 있는 메시지로 커밋한다. 세션 로그는 3줄 이내로 쓴다.
- 담당은 `docs/SPEC.md`의 역할 분담(v2, 팀 확인 필요)을 따른다. 사용한 에이전트와 모델은 세션 로그에 적는다.
- 하위 티켓(W1-07a처럼 부모 ID 뒤에 영문 소문자)의 정의(선행·크기·완료 기준)는 `docs/03-plan.md`에 있고, 상태는 이 파일에서만 관리한다. 브랜치는 시작할 때 `feat/<티켓ID>-<짧은이름>`으로 만들어 적는다.
- 부모 Task는 "(선택)"이 아닌 하위 티켓이 모두 통과했을 때 통과로 바꾼다. 하위 티켓은 부모 Task의 완료 조건을 바꾸지 않는다.
- 하위 티켓을 추가·삭제하거나 다른 주차로 옮기는 것은 사람이 정하고 `docs/03-plan.md`부터 고친다.
